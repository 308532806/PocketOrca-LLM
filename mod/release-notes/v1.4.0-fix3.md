# PocketOrca-LLM v1.4.0 fix3 — NPU 修复 + GPU 旧驱动兼容(二) + UI 修复 + 三引擎测速

本包基于官方 **v1.4.0 release APK**（sha256 `14885aad…e5478`）以"手术式"修改制作，**未改动 dex 与推理逻辑**。

fix3 = fix2 + 补充 OpenCL 2.1 符号兼容 + 状态胶囊 UI 修复。

> 安装：官方版需先卸载；fix1 / fix2 用户可直接覆盖安装（同一签名）。

## 1. NPU(HTP) 启动崩溃修复（自 fix1）

v1.4.0 在 HTP arch > 79 机型（骁龙 8 Elite Gen 5 等）上 NPU 模式崩溃（`fastrpc_mmap failed` / exit 134）：新 DMA64 扩展映射与内置旧 `libcdsprpc.so` 不兼容。修复 = 强制 `opt_dma64 = 0`（`libggml-hexagon.so` 两处字节补丁，回退到 v1.3.8 映射路径，实测无性能损失）。

修复后 `libggml-hexagon.so` sha256 `27713036999a9f76e1b4fafce02346504d787cab676158a11987ecc9c06b9bec` 与社区独立修复一致。

## 2. GPU(OpenCL) 旧驱动兼容（自 fix2，fix3 扩充）

v1.4.0 的 `libggml-opencl.so` 因 `BIND_NOW`（加载期立即绑定）强依赖两个新 OpenCL 符号，旧 Adreno 驱动不导出 → 整个 GPU 引擎无法加载（`cannot locate symbol …`）。

| 符号 | 修复 |
|---|---|
| `clCreateBufferWithProperties`（CL 3.0） | 符号改名 `clCreateBuffer` + 调用点置 `nop`（该调用仅属于默认关闭的 X2 大型缓冲实验路径） |
| `clGetKernelSubGroupInfo`（CL 2.1） | 两个调用点直接返回"查询失败"（走 llama.cpp 既有降级：禁用两个 mamba2 专用 subgroup kernel）+ 符号改名占位保证加载通过 |

**影响说明**：修复使 GPU 引擎在旧驱动设备上恢复可加载；代价是 mamba2 系模型的专用 subgroup kernel 在 GPU 上被禁用（功能不受影响，常规模型无感）。其余一切与官方逐字节一致。

## 3. 状态胶囊开关修复（fix3）

右上角状态胶囊的开关滑块此前永远不动（原版 `setState` 只更新圆点、未同步 `#statusPill` 的 `running/starting` 样式类）。本版修复：**运行中滑块右移并变绿，启动中变黄**，与指示圆点同步。

## 4. 三引擎测速（自 fix1）

Server 页「引擎测速」：用**当前模型**依次实测 NPU / GPU / CPU（生成速度 t/s、提示处理 t/s、加载耗时，标出最快），完成后自动恢复原引擎。无 NPU / 驱动不支持的机型会显示"启动失败"——这是正确的探测结果。
