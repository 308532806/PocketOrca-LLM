# PocketOrca-LLM v1.4.0 fix2 — NPU 启动修复 + GPU 旧驱动兼容 + 三引擎测速

本包基于官方 **v1.4.0 release APK**（sha256 `14885aad…e5478`）以"手术式"修改制作，**未改动 dex 与推理运行时逻辑**。fix2 = fix1（NPU 修复 + 测速）**+ 新增 OpenCL 旧驱动兼容修复**。

> 已安装 fix1 的用户可直接覆盖安装本包（同一签名）；官方版用户需先卸载。

## 1. 修复 NPU(HTP) 引擎无法启动（issue #1）

**症状**：v1.4.0 在 HTP arch > 79 的机型（骁龙 8 Elite Gen 5 / SM8850 等）上，NPU 模式加载模型后首轮 decode 即崩溃：
```
E ggml-hex: HTP0 buffer mapping failed : domain_id 3 size ... error 0x0000000e
terminating due to uncaught exception: ggml-hex: fastrpc_mmap failed
[进程退出] exitCode=134
```

**根因**：v1.4.0 升级的 llama.cpp（`58367713a`，含 PR #29197 "64-bit DMA mappings"）为 arch > 79 启用 DMA64 扩展映射（2 MiB 对齐 + `FASTRPC_MAP_FD_DELAYED_EXTENDED`），而 APK 内置的旧版 `libcdsprpc.so` 无法完成该映射 → `fastrpc_mmap` 返回 `0xe` → abort。

**修复**：把 `libggml-hexagon.so` 中写 `opt_dma64` 的两处 `strb w8,[x9,#2760]` 改为 `strb wzr,[x9,#2760]`（强制 DMA64=0，回退到 v1.3.8 的普通映射路径，实测无性能损失）：

| 文件偏移 | 原字节 | 修改后 |
|---|---|---|
| `0xC6544` | `28 21 2B 39` | `3F 21 2B 39` |
| `0xC997C` | `28 21 2B 39` | `3F 21 2B 39` |

修复后 `libggml-hexagon.so` 的 sha256 与社区独立修复产物一致：
`27713036999a9f76e1b4fafce02346504d787cab676158a11987ecc9c06b9bec`

> 参考：[issue #1](https://github.com/PocketOrca/PocketOrca-LLM/issues/1) 中 qwerkilo 的定位报告；llama.cpp PR #29197。

## 2. 修复 GPU(OpenCL) 引擎在旧 Adreno 驱动上加载失败（新增）

**症状**（例：骁龙 765G / Adreno 620 / Android 12）：
```
[mode] JNI in-process (OpenCL)
[jni error] java.lang.UnsatisfiedLinkError: dlopen failed: cannot locate symbol
  "clCreateBufferWithProperties" referenced by ".../libggml-opencl.so"...
```

**根因**：v1.4.0 的 `libggml-opencl.so` 因 `BIND_NOW`（加载期立即绑定）强依赖 `clCreateBufferWithProperties`（OpenCL 3.0 符号），而部分旧驱动不导出该符号。该符号在整个代码里只用于一处：`GGML_OPENCL_ADRENO_USE_LARGE_BUFFER`（默认**关闭**、X2 类新驱动专属）的"大型缓冲区重试"路径——是一段对旧驱动而言的**死代码**，却阻断了整个库的加载。

**修复**（两处字节补丁）：
- `dynstr @0xF19D`：符号名 `clCreateBufferWithProperties` → `clCreateBuffer`（等长 28 字节，尾部填零；仅改动态字符串表）；
- 调用点 `0x331270`（vaddr `0x335270`）：`bl clCreateBufferWithProperties@plt` → `nop`（该实验路径被静默跳过）。

**影响**：GPU 引擎在旧驱动设备上恢复可加载（其余符号均由真驱动提供）；新驱动设备仅失去上述默认关闭的实验特性。CPU / NPU 路径不受影响（其 exec 子进程本就走内置 stub 壳）。

## 3. 三引擎测速（自 fix1 起）

Server 页「引擎测速」卡片：用**当前已选模型**依次在 NPU → GPU → CPU 上启动服务（与正常使用完全一致的路径），显示每个引擎的**生成速度 t/s / 提示处理 t/s / 加载耗时**，标出最快引擎；测完自动恢复原引擎，可随时中止。

> 注：部分机型没有可用 NPU（如骁龙 7 系旧平台）或 GPU 驱动不受支持，测速会对相应引擎显示"启动失败"——这是正确的探测结果。
