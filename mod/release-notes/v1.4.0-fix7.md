# PocketOrca-LLM v1.4.0 fix7 — 状态恢复 + 参数展示 + 推荐卡片折叠

fix7 = fix6 全部内容 + 3 项体验修复。

> 安装：官方版需先卸载；fix1~fix6 用户可直接覆盖安装（同一签名）。

## 修复内容

### 1. 切换标签页后状态误显示"已关闭"（fix7）

**现象**：服务运行中切到其它标签页再切回来，偶尔显示未运行，过一会儿才恢复正常。

**根因**：WebView 页面重建时 JS 的 `state` 变量重置为"未运行"，而真实状态的重新查询要等 10 秒轮询周期。

**修复**：页面初始化时**立即**从 Java 侧查询服务真实状态并恢复 UI，不再依赖轮询。

### 2. 模型卡片显示当前生效参数（fix7）

模型卡片元信息行现在显示：**体积 · 上下文 · 线程数 · ubatch · KV 卸载**

例：`1.45 GB · ctx 4K · 4t · ub 256 · KV关`

调整上下文/线程/ubatch/KV 开关时**实时刷新**，改完参数不用启动就能确认当前配置。

### 3. 推荐参数卡片改为可折叠（fix7）

推荐参数卡片改成与"参数"卡片一致的**抽屉式折叠**（默认收起，点击展开/收起，状态被记住），不再常驻占屏。

## 上游兼容性说明（bug 反馈 #2：外部客户端看到的模型名含路径）

外部客户端通过 `/v1/models` 列模型时看到的是**模型文件完整路径**（llama-server 默认行为，路径即 id）。

llama-server 原生支持 `--alias` 参数可解决，但**传入该参数需要改 Java 层启动逻辑**，超出本修复包"不动 dex"的边界。变通方案：客户端手动填模型名（多数客户端支持），或接受路径名（不影响功能）。

## 图片生成模型（bug 反馈 #5：评估结论）

**暂不可行**。原因：

1. llama.cpp 是**文本 LLM 推理引擎**，不支持扩散模型（Stable Diffusion 类）的计算图
2. 本包技术路线是"APK 手术"（只改 assets + 字节级 .so 补丁），无法引入新引擎
3. 需要的改动 = 集成稳定扩散运行时 + 全新 UI + Java 层图像管线 ≈ 重写半个 App
